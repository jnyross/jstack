### Capture

**You own the slug. Chat is not memory.**

A fact, decision, or pattern that will be asked again. Done is a slug. `get_page` after `put_page`. Uncertain claims labeled.

1. Search for an existing page (`search`, `query`, `list_pages`). Update beats a duplicate.
2. Write concise markdown with `put_page`. Provenance in the page, not a vibes summary. Slug, gmail id, event id, or URL on load-bearing claims.
3. Verify by reading the saved page back with `get_page`. Report the slug.
4. If it will not be retrieved, do not write it. Capture without retrieval is how action lists rot.

Nothing else unless the source of the fact is live mail or calendar. Then cite that id on the page.

**Reply:** the slug, whether it was an update or a new page, and the one claim that earned the write. If you refused to capture, say why.
